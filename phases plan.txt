# Media Manager - Detailed Phased Implementation Plan

## Project Overview
A self-hosted media management system running on Ubuntu that organizes, archives, and tracks movies/TV shows with a web dashboard accessible from Windows machines.

**Architecture**: Ubuntu Backend (FastAPI + Python) + Web Dashboard (HTML/CSS/JS) + Windows Toast Notifications

## 📦 Phase 1: Core Database & Foundation
*Estimated Effort: 3-4 hours*

### 1.1 Database Schema Design

**Table: `media_items`**
- Store all archived media metadata
- Fields: id (primary key), original_path, title, year, tmdb_id, media_type (movie/tv), season_number, episode_number, final_path, archived_at (timestamp), watched (boolean), metadata (JSON), created_at (timestamp)

**Table: `archive_tracker`**
- Track shows/movies for future release notifications
- Fields: id (primary key), tmdb_id, media_type (movie/tv), title, current_season_archived (integer), latest_known_season (integer), movie_release_status (text), last_checked (timestamp), pending_notification (boolean), notification_sent_at (timestamp), created_at (timestamp)
- Unique constraint on (tmdb_id, media_type)

**Table: `operation_log`**
- Audit trail of all operations
- Fields: id (primary key), operation_type (archive/rename/purge/tracker_check), media_id (foreign key), details (JSON), status (success/failed/pending), error_message (text), created_at (timestamp)

### 1.2 Database Layer Implementation

**File: `app/database.py`**
- [ ] Implement connection management using sqlite3 with context managers
- [ ] Create CRUD operations for each table (create, read, update, delete)
- [ ] Add migration system for future schema changes
- [ ] Implement helper functions: `execute_query()`, `fetch_all()`, `fetch_one()`
- [ ] Add database initialization script that creates all tables
- [ ] Implement database connection pooling for concurrent access

### 1.3 Configuration Management

**File: `config.yaml`**
- [ ] Define paths: active_dir, archive_movies, archive_tv
- [ ] Define TMDB settings: api_key, language
- [ ] Define subtitle settings: keep_languages, delete_extensions
- [ ] Define tracker settings: cron_time, notification_ttl_days
- [ ] Define database path
- [ ] Define logging level and file path

### 1.4 Configuration Loader

**File: `app/config_loader.py`**
- [ ] Parse YAML configuration file
- [ ] Validate all required paths exist
- [ ] Create default configuration if file is missing
- [ ] Support environment variable overrides (for sensitive data)
- [ ] Provide typed access to configuration values

## 🎬 Phase 2: TMDB Integration (Hybrid Mode)
*Estimated Effort: 4-5 hours*

### 2.1 Primary API Client

**File: `app/core/tmdb_client.py`** (Part 1)
- [ ] Install `tmdbv3api` package
- [ ] Implement `TMDBClient` class with API mode
- [ ] Methods to implement:
  - `search_movie(title, year)` → returns metadata
  - `search_tv(title)` → returns metadata
  - `get_movie_details(tmdb_id)` → detailed movie info
  - `get_tv_details(tmdb_id)` → detailed TV show info
  - `get_collection_movies(collection_id)` → sequel/prequel tracking
  - `parse_filename(filename)` → extract title/season/episode

### 2.2 Web Scraper Fallback

**File: `app/core/tmdb_scraper.py`**
- [ ] Install required packages: `beautifulsoup4`, `requests`, `fake-useragent`, `lxml`
- [ ] Implement `TMDBScraper` class
- [ ] Features to implement:
  - Rate limiting (2-second delay between requests)
  - Rotating user agents (random browser fingerprints)
  - Session reuse (maintain cookies and headers)
  - Error handling with automatic retries
- [ ] Methods mirroring API client:
  - `search_movie(title, year)` → scrape search results
  - `search_tv(title)` → scrape search results
  - `get_movie_details(tmdb_id)` → scrape movie page
  - `get_tv_details(tmdb_id)` → scrape TV show page
  - `get_collection_movies(collection_id)` → scrape collection page

### 2.3 Unified Client

**File: `app/core/tmdb_client.py`** (Part 2)
- [ ] Combine API + Scraper into single unified class
- [ ] Auto-detect API key presence (use API if valid, else scraper)
- [ ] Implement API → Scraper fallback on failure
- [ ] Ensure consistent response format regardless of source
- [ ] Add logging to indicate which mode is being used
- [ ] Cache results to minimize external calls

### 2.4 Testing & Validation
- [ ] Test with valid API key
- [ ] Test without API key (scraper mode only)
- [ ] Test API failure → scraper fallback
- [ ] Validate response format consistency between modes
- [ ] Test with edge cases (empty results, special characters)

## 📂 Phase 3: Core File Processing Logic
*Estimated Effort: 6-8 hours*

### 3.1 Media Scanner

**File: `app/core/scanner.py`**
- [ ] Implement recursive directory traversal
- [ ] Identify video files by extension (.mkv, .mp4, .avi, .mov, .wmv, .flv, .webm)
- [ ] Group files by directory (for multi-file movies)
- [ ] Parse filenames using regex patterns
- [ ] Collect subtitle file information (.srt, .ass, .ssa)
- [ ] Generate file size and modification timestamps
- [ ] Return structured file information

### 3.2 Renamer Engine

**File: `app/core/renamer.py`**
- [ ] Generate movie folder structure:
  - Format: `Movie Name (Year)/Movie Name (Year).ext`
- [ ] Generate TV show structure:
  - Format: `Show Name/Season XX/Show Name - SXXEYY - Episode Title.ext`
- [ ] Fetch episode titles from TMDB API/scraper
- [ ] Sanitize filenames (remove invalid characters for file system)
- [ ] Implement artwork handling:
  - Download posters (poster.jpg)
  - Download fanart/backdrops (fanart.jpg)
  - Create NFO files for media center compatibility (optional)
- [ ] Handle file renaming conflicts (add suffixes if needed)

### 3.3 Subtitle Purger

**File: `app/core/subtitle_purger.py`**
- [ ] Recursively find all subtitle files (.srt, .ass, .ssa)
- [ ] Implement pattern matching for language codes:
  - Keep: .en., .eng., .english.
  - Delete: All other language codes
- [ ] Implement dry-run mode (preview without deletion)
- [ ] Add empty folder cleanup after purging
- [ ] Provide detailed logging of kept/deleted files
- [ ] Handle edge cases (no subtitle files, non-standard naming)

### 3.4 Archiver

**File: `app/core/archiver.py`**
- [ ] Copy files using shutil.copy2 (preserve metadata)
- [ ] Create destination directories automatically
- [ ] Log operations to database (operation_log table)
- [ ] Update `media_items` table with final paths
- [ ] Handle errors gracefully (permissions, space issues)
- [ ] **Note**: Checksum verification deferred per initial requirements

## ⚠️ Risk Matrix

| Risk | Probability | Impact | Mitigation |
|------|-------------|--------|------------|
| TMDB website changes breaking scraper | Medium | High | API key fallback; monitoring |
| External HDD disconnection during archive | Low | High | Error handling; retry logic |
| Large file transfers timeout | Medium | Medium | Background tasks; chunking |
| SQLite corruption | Low | High | Regular backups; WAL mode |
| Rate limiting from TMDB | Low | Low | Use API key; caching |
| Windows firewall blocking requests | Medium | Medium | Documentation; setup script |
| Regex parsing fails for unusual filenames | Medium | Medium | User override; manual input |
